- 2026-09-21 #0: workspace with a `core` lib + thin binaries — so specs test one crate's pub API and shells stay untested-by-design
- 2026-09-21 #0: sqlx + SQLite (one file, WAL) with a Litestream sidecar to S3 over Turso — because sqlx has no libSQL driver, the data is ~0.3 GB/month at 10K users, and cost is a wash (<$10/mo either way); Turso stays possible as a second `BillStore` impl
- 2026-09-21 #0: raw emails and attachments are S3 objects, only structured rows go in the DB — because attachments are ~100× the row data (~30 GB/month vs ~0.3 GB)
- 2026-09-21 #0: money = integer minor units + ISO currency code, no decimal crate — because it is exact, sortable, and trivially stored as INTEGER
- 2026-09-21 #0: `time` over `jiff`/`chrono` for dates — because sqlx ships a native `time` feature, so no glue types
- 2026-09-21 #0: allowed deps += sqlx, mail-parser, pdf-extract, serde, serde_json, sha2, time — pinned in the workspace so implementers only add `{ workspace = true }` in their crate
- 2026-09-21 #1: `Bill` is built via `TryFrom<BillDraft>` (plain struct, pub fields) with `#[serde(try_from, into)]` over a many-argument constructor — because one entry point enforces the status/field invariants for both code and JSON
- 2026-09-23 #2: `BillStore` is an async trait returning boxed `Send` futures (`dyn`-compatible, no `async-trait` crate) over generics or a sync trait — because sqlx is async, `ingest` and the server want `&dyn BillStore` so the in-memory fake can stand in, and it adds no dependency
- 2026-09-24 #3: `MimeType` is a normalised `type/subtype` newtype over an enum, and `Envelope`/`Document` are pub-field records over accessor types — because the mime set is open (`extract` owns what a mime means) and downstream modules' tests build envelopes by hand
- 2026-09-24 #4: `Extractor::extract` takes `&Envelope` (not `&Document`), `TextExtractor` is a hand-written scanner (no `regex` dependency), and `merge` breaks confidence ties by a structural order on the value then the span — because the vendor fallback needs the sender, the token grammar is small enough that a dependency is not worth a decision, and a total order is what makes merge order-insensitive by construction
- 2026-09-28 #5: `Extraction` gains `notes: BTreeSet<Note>` (first: `NoTextLayer`) over a per-extractor reason type, `PdfTextExtractor::text_layer` is a pub seam wrapped in `catch_unwind`, and one corrupt PDF fails the whole `extract` call — because a set keeps `merge` order-insensitive and idempotent, pdf-extract 0.12 panics on well-formed inputs with missing font resources (spike-verified), and a silent partial result would be dishonest about what was read
- 2026-09-30 #6: bill id = lowercase hex of sha256(raw) over a random id, `Extracted` requires amount at confidence ≥ 50 plus vendor plus period, and an extractor `Err` stores nothing — because a deterministic id keeps replay idempotent without a `uuid` dependency, `Bill::try_from` already demands all three fields so the issue's amount-only rule could not build an `Extracted` bill, and a corrupt attachment is a problem to surface rather than silently file as `NeedsReview`
- 2026-10-02 #7: extractor composition is `core::extract::Chain` (not server-side glue), extractor errors answer 400 and store/bill errors 500 with a fixed body, a malformed bill id is a 404, and the body limit is 25 MiB — because binaries never compute a domain value and the CLI needs the same chain, a corrupt attachment is the caller's malformed input while a store failure is ours to hide, an id that can never match is simply not found, and axum's 2 MB default would reject real PDF bills
- 2026-10-02 #8: the CLI is a bin-only crate whose testable surface is the process (exit code, stdout, DB side effects via `assert_cmd`), its three-token grammar is parsed by hand instead of adding `clap`, usage errors exit 2 while runtime errors exit 1, and the message is read before the store is opened — because a lib would invite testing internals of a shell that computes no domain value, a dependency is a decision the grammar does not earn, a replay loop needs to tell "bad invocation" from "bad bill", and a typo in a path should never leave an empty DB file behind
- 2026-10-03 #21: `Extractor::extract` returns a boxed `Send` future (the `BillStore` pattern, no `async-trait`) over blocking inside the trait, completeness is one `Extraction::is_complete` rule shared by `ingest` and the new `Escalate` combinator, and `Escalate` merges rather than replaces — because the LLM extractor (#23) is network-bound, a sync trait would force `block_on` inside core, two copies of the status rule would drift, and the cheap extractor's higher-confidence fields must survive escalation
- 2026-10-03 #23: `rig-core` (rustls + reqwest only) over `genai` for the LLM client, `pdftoppm` shelled out behind a `Rasterizer` trait over a Rust PDF rasterizer crate, PDF pages rasterized to PNG for every provider by default (switchable per provider), Ollama `gemma4:latest` for dev and Anthropic/OpenAI in prod, workspace MSRV 1.85 → 1.95 — because genai's Ollama adapter silently drops PDF parts and ignores JSON-schema output so the dev path would not exercise the prod path, poppler is already a system package while a Rust rasterizer is a heavier decision, one delivery path means the local model tests the production code, and rig declares MSRV 1.95
- 2026-10-03 #26: `LlmExtractor` degrades on a client error or malformed reply (empty extraction + `Note::LlmUnavailable`/`LlmMalformed`) instead of `Err`, every schema field is required-but-nullable, model confidence is capped at 70, the binaries wrap the chain in `Escalate` at `EXTRACTED_MIN_CONFIDENCE` only when `HAUZ_LLM_PROVIDER` is set, and `serde_json` becomes a regular core dependency (already allowed) rather than reaching through rig's re-export — because an outage must leave the bill `NeedsReview` with the heuristic fields rather than 400 the caller (decision #7 keeps `Err` for malformed input), the #23 spike showed all-`Option` fields let the model omit values it saw while claiming 100, a model answer is never ground truth, the default dev path must stay dependency-free, and a dependency used in library code is declared, not borrowed
- 2026-10-03 #28: a bare `$` is not a currency marker in `TextExtractor` (the numeral beside it is not an amount), while `COP$`/`USD$`/`US$` and a 3-letter code beside the numeral still resolve, over a sender-TLD locale guess or a configured default currency — because four of seven corpus bills are Colombian and `$`→`USD` stored a wrong currency as if understood, an absent amount leaves the bill honestly `NeedsReview` and lets the LLM pass's `COP` amount win the merge, and a guessed default is the very behaviour the Purpose forbids
- 2026-10-03 #32: a std-only `zip` module (central-directory walk + hand-rolled RFC 1951 inflate, CRC-checked, 64 MiB entry cap) over declaring `flate2` or `zip` — because the #27 spike proved 248 lines decode every corpus entry and 30 random zlib buffers bit-exactly, `flate2` is only a transitive crate of `lopdf` and declaring it is a dependency decision the human has not taken, and zip64/encryption/descriptors are reported `Unsupported` rather than guessed around
- 2026-10-03 #27: DIAN e-invoices are read exactly by `XmlInvoiceExtractor`, a std-only local-name XML plucker (CDATA + five entities) over `core::zip`, placed first in both binaries' chains, with every lookup scoped to its parent element under `Invoice`, confidence 100, a corrupt zip as `Error::Zip` and an unparsable value as an omitted field, over declaring `quick-xml` — because the spike showed the UBL fields sit at fixed parent chains inside one CDATA `Invoice`, a general parser is a dependency decision the five fields do not earn, cycle 1 review proved an unscoped forward scan reads the customer or the outer `AttachedDocument` instead, and a period is never guessed from the issue date so invoices without `InvoicePeriod` stay `NeedsReview`
- 2026-10-04 #37: `Extracted` requires amount + vendor + (period or issue date), with `issued` persisted, replacing decision #6's amount + vendor + period, and no period is ever derived from the issue date — because the 2026-10-04 corpus replay put 0/7 real bills in `Extracted` since receipts and most DIAN invoices state no period, while an issue date is not the period it covers (a utility bill issued 1 Sep bills August, a subscription receipt pays ahead), so deriving one would be the guess the Purpose forbids
- 2026-10-04 #42: mail is fetched from Gmail through the Gmail API (OAuth refresh token, `gmail.readonly`, label poll, in-process `ingest`) over a forwarding bridge (Apps Script, Cloudflare Email Worker, Postmark/Mailgun inbound), reversing "fetching mail is out of scope"; `reqwest` is declared and the few REST calls are hand-rolled over a Google SDK crate; polling before Pub/Sub push — because the human already runs a Google Cloud project and wants Google SSO later (same project, per-user consent if hauz ever serves others), a Rust fetcher is versioned and tested like the rest and can backfill the inbox, `reqwest` is already compiled in via rig-core, and the restricted scope's risks (7-day token expiry in Testing mode, whole-mailbox read) are handled operationally: consent screen "In production", read-only scope, token only in the environment
- 2026-10-04 #41: allowed deps += `ratatui`, `crossterm` for a read-only `crates/tui` bill browser — explicit human yes in planning; a TUI is the local (and later on-Droplet) debugging view until a web UI exists, and it stays read-only so the server remains the single writer
- 2026-10-04 #22: hosting is one DigitalOcean Droplet running Docker Compose (server + Litestream) replicating to DigitalOcean Spaces, moving to AWS only if the project scales, over DO App Platform — because Spaces speaks the S3 API so the move is configuration, and App Platform's ephemeral disk works against a single SQLite file
- 2026-10-04 #36: a zip attachment `core::zip` reports `Unsupported` (data descriptor, zip64, encryption, other methods, oversized entry) degrades to `Note::UnreadableArchive { document }` while a `Malformed` one stays `Error::Zip` (400), deciding by error class rather than by content, with notes still unpersisted — because an unreadable archive's contents cannot be inspected for an `Invoice`, an unsupported archive is a valid file our reader cannot open and must not cost the bill beside it, while corrupt bytes remain the caller's malformed input exactly like a corrupt PDF (decisions #5/#7); adding zip features would shrink the problem, not remove it
- 2026-10-04 #44: CI is one GitHub Actions job (`.github/workflows/verify.yml`) running `.claude/scripts/verify.sh` on every PR and on pushes to `main`, on the toolchain read from `Cargo.toml`'s `rust-version` and cached with `Swatinem/rust-cache@v2`, with no secrets, nextest or pdftoppm — because verify.sh is already the single gate the reviewer trusts, so CI must run exactly it, and reading the MSRV from Cargo.toml keeps one source of truth while catching code that silently depends on the author's newer local compiler
- 2026-10-04 #38: `Currency::new` accepts only active ISO 4217 alphabetic codes, from a private sorted const table in `bill` (funds and real `X` codes in, `XXX`/`XTS` and withdrawn codes out), with no dependency and no new `pub` item; a stored row with a non-ISO code is `store::Error::Corrupt` on read, not skipped or migrated — because the corpus replay stored a Colombian tax ID (`NIT 860063875-0`) as money when any three uppercase letters counted as a currency, every extractor already omits an amount whose code fails `Currency::new`, and hiding a stored record would be the silent guess the Purpose forbids
- 2026-10-05 #39: `Envelope` exposes `sender_name` (the decoded, trimmed display name of the same address `sender` comes from; `None` when absent, blank or merely repeating the address) and `TextExtractor` prefers it over the sender domain as vendor at the unchanged fallback confidence 20, kept verbatim (no prefix stripping, no alias table) — because the 2026-10-04 corpus replay stored every non-DIAN vendor as a domain (`stripe.com` for a DeepLearning.AI receipt) while the display name names the real vendor, and keeping the header-derived vendor at 20 lets any document-sourced vendor (XML at 100, the LLM) still win the merge
- 2026-10-05 #41: the TUI reads through a new `SqliteStore::open_read_only` (read-only, never creates the file, no migrations or journal-mode change) over opening a normal writer handle, `crates/tui` is lib + bin with `[e2e]`-only tests (`TestBackend` renders of the pub `App`/`draw`, `assert_cmd` for the process) mirroring the GPUI rule, the DB is loaded before the terminal opens, amounts render at two decimals like the extractors assume, and a corrupt row fails the whole view — because a browser that could migrate or create a DB would become a second writer beside the server, view logic must be pub to be testable while the terminal loop needs a TTY no test has, an open failure must print plainly rather than inside raw mode, and hiding a corrupt row would be the silent guess the Purpose forbids
- 2026-10-05 #40: every matched `/v1` route sits behind one `route_layer` bearer guard (`Authorization: Bearer <token>`, scheme case-insensitive, single space, constant-time byte compare that leaks only length) against a single `HAUZ_API_TOKEN` carried as a pub `ApiToken` (blank ⇒ `None`, `Debug` redacted) that `AppState::new` requires, answering an identical 401 `{"error":"unauthorized"}` + `WWW-Authenticate: Bearer` for missing and wrong tokens before the body is read, and `main.rs` refuses to start without the token — because the webhook must not be open once deployed, a required constructor argument makes an unauthenticated server unrepresentable instead of a forgotten env var silently opening it, checking before the body keeps unauthenticated clients from making the server buffer 25 MiB, and users/sessions/rate limiting stay a later issue
